# 80 · Project pages, then the UI overhaul

Goal: the owner can trust the AI to keep building a project, and the hub feels calm enough to build in.
Order: **pages first → UI overhaul → owner tests.**

## Phase 1: pages (this branch)

| Page | What it does |
| --- | --- |
| **Mission** | The project at a glance: the goal, what the AI is doing now, what's next, what waits on you. A Continue/Pause button and the checkpoint switch. |
| **Checkpoints** | When a roadmap block is marked done, the AI stops picking up new cards (auto-run off) and Activity says "Checkpoint". You look, then press Continue. On by default. |
| **Journey** | Roadmap, Progress, Trail and Flow together in one view: progress numbers on top, the roadmap blocks, the card map, then the latest work. Replaces four separate tabs in the side panel. |
| **Toolbox in project settings** | Tools, keys and links move into the project's settings dialog. Hidden from the bottom bar by default (Customize can bring it back). |
| **Insights under the board** | Below the cards: a strip of swipeable pages (progress, where cards are, who is working, recent work). |

## Phase 2: UI overhaul

- One home for each tool; no duplicates between the bottom bar, side panel and page.
- One button/card/chip set used everywhere (sizes, radius, spacing).
- Top bar shows only chips that need you; the rest in one status menu.
- Every empty panel says what to do next, with one button.
- Half-screen and tablet pass on every page.

## Phase 3: owner tests

The owner builds a real project with it. Notes go into a new round.

## Later

- Budget and time limit per project, shown on Mission.
- Daily summary on the tablet: done, stuck, spent.
